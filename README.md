# KII Application Portal

Run `.\start.bat` from this folder, or run `python -m http.server 8090`.
Keep the terminal open; press Ctrl+C to stop the server.

- Applicant portal: http://localhost:8090/index.html
- Staff portal: http://localhost:8090/admin-login.html

This is a static frontend. Accounts and application records use localStorage;
uploads use IndexedDB. Applicant and staff views share data only in the same
browser profile and origin. Email messages are logged locally.

## Project structure

- Root HTML files: applicant entry, authentication, application, dashboard and staff pages.
- `js/common.js`: shared storage, authentication helpers, dates and HTML escaping.
- `js/auth.js`: applicant sign-up and sign-in.
- `js/application-merged.js`: current ten-step application and draft migration (older drafts are upgraded automatically).
- `js/application-legacy.js`: original fourteen-section renderer, loaded for
  older submitted or withdrawn applications. It is required compatibility code.
- `js/application-locations.js` and `js/world-cities.csv`: searchable locations,
  universities and postal-code suggestions; source attribution is in the JavaScript.
- `js/dashboard.js`: applicant ideas, tasks, messages and milestones.
- `js/ams.js`: staff roles, records, workflow and applicant synchronization.
- `js/admin.js`: staff management screens, including the Master Admin **Form Builder**
  (Staff portal → Form Builder): edit, add, hide, reorder and delete application questions.
- `js/form-schema.js`: generated list of built-in questions used by the Form Builder.
  Regenerate after changing the form schema with `npm run form-schema`.
- `docs/KII-AMS-Review-and-Engineering-Brief.md`: system review and the production rebuild brief.
- `css/`: shared applicant styles and staff styles.
- `tests/`: current form, legacy/staff, workflow and browser regression checks.

## Development checks

The application itself does not need Node.js or npm. For tests, install a current
Node.js LTS version (22.13 or newer in the 22.x series, or 24+) and run:

```powershell
npm ci
npm test
npm run test:browser
```

The browser test uses installed Google Chrome. To use installed Microsoft Edge:

```powershell
$env:KII_BROWSER_CHANNEL = "msedge"
npm run test:browser
```

Tests use isolated browser storage and local request interception. They do not
start a server or modify applicant records in your normal browser. Screenshots
are temporary and deleted when the browser test finishes.

`node_modules` is generated by `npm ci`; it can be deleted after testing without
affecting the portals. `package-lock.json` pins the test dependencies.

The video fixture `tests/fixtures/statement.mp4` is the CC0 flower sample from
https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4, used to
verify real MP4 duration and file storage.
